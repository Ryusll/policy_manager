# 플랜 × 권한 점검표

작성일: 2026-08-22 (T-59)
대상: Starter / Pro / Enterprise × admin / editor / viewer

---

## 0. 이 문서를 쓰는 방법

**API 차단은 자동 검증한다.** 27칸을 매번 눌러 보는 점검표는 결국 아무도 돌리지 않고,
그러는 사이 유료 기능이 열려 있어도 모른다. 그래서 서버 쪽 403/200은 통합 테스트가 맡는다.

```
npm run test:int -- tests/integration/plan-role-matrix.int.test.ts
```

**이 문서에는 자동 검증이 볼 수 없는 것만 남겼다** — 메뉴가 실제로 사라지는지, 버튼이
눌리지 않는지, 막혔을 때 안내 문구가 나오는지. 요청은 막혔는데 버튼은 살아 있으면
사용자는 눌러 보고 오류를 만난다. 그건 API 테스트로 잡히지 않는다.

점검 시점: **플랜 정책이나 역할 가드를 바꾼 릴리스 전.** 평상시에는 자동 검증으로 충분하다.

### 계정 준비

플랜 변경은 `global_admin` 의 플랫폼 관리 화면(`/admin`)에서 하거나, 개발 환경이면 DB에서 직접 바꾼다.

```sh
docker compose exec -T postgres sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "UPDATE tenants SET plan='"'"'pro'"'"' WHERE slug='"'"'회사슬러그'"'"';"'
```

> **플랜을 바꾼 뒤에는 반드시 다시 로그인한다.** 플랜은 액세스 토큰에 담겨 있어서,
> 로그아웃하지 않으면 예전 플랜으로 계속 동작한다. 점검 중 "왜 안 바뀌지"의 대부분이 이것이다.

## 1. 자동 검증이 이미 덮는 범위 (참고용 — 손으로 하지 않는다)

`tests/integration/plan-role-matrix.int.test.ts` 84건. 표는 기대값을 그대로 옮긴 것이다.

| 대상 | Starter | Pro | Enterprise |
|---|---|---|---|
| `GET /templates` | 전 역할 403 | 전 역할 200 | 전 역할 200 |
| `POST /templates` | 전 역할 403 | admin 201 / 나머지 403 | admin 201 / 나머지 403 |
| `GET /integrations/api-access` | 전 역할 403 | 전 역할 403 | 전 역할 200 |
| `GET /tenant-branding` | 전 역할 200 | 전 역할 200 | 전 역할 200 |
| `PUT /tenant-branding` | 전 역할 403 | admin 200 / 나머지 403 | admin 200 / 나머지 403 |
| `GET /audit-logs` | admin 200 / 나머지 403 | 〃 | 〃 |
| `POST /users` | admin 201 / 나머지 403 | 〃 | 〃 |
| `POST /policies` | admin·editor 201 / viewer 403 | 〃 | 〃 |
| `GET /platform-admin/tenants` | 전 역할 403 | 전 역할 403 | 전 역할 403 |

**403의 출처**: 가드 순서는 JwtAuth → Plan → Roles 다. 플랜과 역할이 둘 다 모자라면
**플랜 쪽 메시지**(`This feature requires pro plan or higher`)가 나오고, 플랜만 충족하면
역할 메시지(`Insufficient permissions`)가 나온다. 상태 코드는 어느 쪽이든 403이다.

## 2. 손으로 볼 것 — 화면 노출

각 칸은 **해당 플랜 + 해당 역할로 로그인한 상태**에서 본다.

### 2-1. 좌측 메뉴

| # | 확인 | Starter | Pro | Enterprise | 결과 |
|---|---|---|---|---|---|
| 1 | `API 연동` 메뉴 | 안 보임 | 안 보임 | 보임 | ☐ |
| 2 | viewer 로그인 시 메뉴 | `검색`만 | `검색`만 | `검색`만 | ☐ |
| 3 | `플랫폼 관리` 메뉴 | 안 보임(`global_admin` 제외) | 〃 | 〃 | ☐ |

> viewer 는 `/search`·`/policies/:id`·`/about` 밖으로 주소를 직접 쳐도 `/search` 로 돌아온다.
> 주소창에 `/settings` 를 넣어 확인한다.

## 3. 강등 시 동작 (알려진 제한)

| 상황 | 현재 동작 | 비고 |
|---|---|---|
| Pro → Starter 강등 후 기존 브랜딩 | **계속 표시된다** | 조회는 플랜을 안 본다. 막으면 화면이 깨지는 방향이라 별도 결정으로 미뤘다 ([ADR-0014](../10_ADR_의사결정기록/ADR.md)) |
| Enterprise → Pro 강등 후 자유 HTML 템플릿 | 기존 템플릿은 남고 **편집·복원은 거부** | T-58 |
| 강등 후 규정 수가 상한 초과 | 기존 규정은 남고 **추가 생성만 거부** | 데이터를 지우지 않는다 |
