# 시스템 아키텍처

작성일: 2026-07-21
근거: 실제 코드(apps/api, apps/web, docker-compose.yml, prisma/schema.prisma) + `docs/policy_manager_개발정의서.docx`, `docs/VEDA_FeatureList.docx`

## 1. 개요

policy_manager는 멀티테넌트(회사 단위) SaaS로, 하나의 백엔드·DB를 여러 테넌트(Tenant)가 공유하고 `tenantId`로 데이터를 격리하는 구조다.

## 2. 구성도

```
[Browser]
   |  HTTPS
   v
[web: nginx (80)] --serves static React SPA--> [Vite build: apps/web]
   |  /api/* 프록시
   v
[api: NestJS (3000, 호스트 노출 3001)]
   |         |            |
   v         v            v
[postgres] [redis]     [minio]
 (5432,    (6379,      (9000/9001,
  호스트    호스트       파일 스토리지:
  5433)     6380)        규정 첨부파일)
```

- 브라우저는 `web` 컨테이너(nginx)만 직접 호출하고, nginx가 `/api/`를 `api` 컨테이너로 프록시한다 (`apps/web/nginx.conf`).
- `PUBLIC_URL` 하나로 CORS 허용 오리진, OAuth 콜백 URL을 함께 구성한다 (`docker-compose.yml`, `apps/api/src/main.ts`).

## 3. 백엔드 (apps/api)

- 프레임워크: NestJS 10, TypeScript
- ORM: Prisma 5 (PostgreSQL)
- 인증: `@nestjs/jwt` + `@nestjs/passport`(Google OAuth strategy), bcrypt 비밀번호 해시
- 검증: 전역 `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`) — `apps/api/src/main.ts`
- 보안 미들웨어: `helmet()`, `cookie-parser`, `@nestjs/throttler`(레이트리밋)
- API 문서: Swagger — `/api/docs` (전역 prefix `api`)
- 파일 처리: PDF 텍스트 추출을 위해 런타임 이미지에 Python(`pdfplumber`, `pymupdf`)을 설치하도록 `apps/api/Dockerfile`에 정의되어 있고, Node에서 `spawnSync`로 호출한다(`regulation-parse.service.ts`). ⚠️ **단, 이 pip 설치는 현재 Alpine(musl) 환경에서 실패해 이미지 빌드를 막는다** — [13_기술부채대장](../13_기술부채대장/기술부채_대장.md) #7 참고(미해결). 2026-07-21 스모크 테스트에서는 해당 설치를 임시 제외하고 코어 스택을 검증했다.
- 파일 저장소: MinIO(S3 호환), `STORAGE_TYPE=minio` 환경변수로 전환

### 모듈 구성 (`apps/api/src/*`)

## 4. 프론트엔드 (apps/web)

- React 18 + Vite, TypeScript
- 라우팅: `react-router-dom` (`App.tsx`) — 인증 가드(`PrivateRoute`)에서 `viewer` 역할은 검색·규정상세·소개만 접근 가능하도록, `platform-admin`/`admin` 경로는 `global_admin`만 접근하도록 제한
- 서버 상태: TanStack Query
- 클라이언트 상태: Zustand (`authStore`, `brandStore`, `themeStore`, `toastStore` 등)
- 스타일: Tailwind CSS + CSS 변수 기반 테마 토큰(`--color-navy-*`, `--color-gold-*`) — `index.css`, `tailwind.config.js`
- 국제화: `i18n/messages.ts` (ko/en)
- 문서 파싱 보조 라이브러리: `mammoth`(DOCX), `pdfjs-dist`(PDF) — 클라이언트 측 미리보기용

## 5. 데이터베이스

- PostgreSQL 15, 확장: `pg_bigm` (한국어 검색 성능)
- 상세 ERD는 [08_ERD_테이블명세서](../08_ERD_테이블명세서/ERD_테이블명세서.md) 참고
- 스키마 관리: Prisma migrations 12건 존재하나 **초기 스키마를 생성하는 baseline 마이그레이션이 없음** — 컨테이너 기동 시 `prisma migrate deploy` 실패하면 `prisma db push --accept-data-loss`로 폴백 (`docker-entrypoint.sh`). **2026-07-21 스모크 테스트에서 실제로 재현됨**(`migrate deploy`가 `relation "users" does not exist`로 실패 → 폴백으로 기동). 즉 운영 스키마가 마이그레이션 이력만으로 재현되지 않으며 폴백에 데이터 손실 위험이 있음 ([13_기술부채대장](../13_기술부채대장/기술부채_대장.md) #8, [ADR-0005](../10_ADR_의사결정기록/ADR.md))

## 6. 인프라 / 배포

- Docker Compose 단일 호스트 배포: `postgres`, `redis`, `minio`, `api`, `web`
- `api` 컨테이너 기동 시 자동 수행: `prisma migrate deploy` → (실패 시) `prisma db push` → 데모 데이터 시드
- 상세 배포/롤백 절차는 [16_Runbook_배포롤백](../16_Runbook_배포롤백/Runbook_배포롤백.md) 참고

## 7. 인증·권한 모델

- 테넌트 내 역할(`Role`): `admin` / `editor` / `viewer`
- 플랫폼 역할(`PlatformRole`): `none` / `global_admin` (SaaS 운영자, 테넌트 간 통합 관리 콘솔 접근)
- 인증 방식: 이메일/비밀번호 + Google OAuth, JWT access/refresh 토큰(자동 갱신)

## 8. 멀티테넌시 · 플랜

- 모든 핵심 테이블에 `tenantId` FK로 데이터 격리 (DB 레벨 RLS는 미적용, 애플리케이션 레벨 필터링에 의존 — 보안 검토서 참고)
- 플랜(`PlanTier`): `starter` / `pro` / `enterprise` — 규정 개수·사용자 수 상한은 `apps/api/src/common/plan-limits.ts` 참고
- 결제: `BillingCustomer`/`BillingSubscription`/`BillingPayment` 모델, 현재는 mock 프로바이더만 동작 (실 PG 미연동)
