## 1. 제품 개요

policy_manager는 회사(고객사)가 사내 규정을 법령정보센터 수준의 경험(조·항·목 구조, 개정 이력, 검색, 인쇄 양식)으로 편집·열람·관리할 수 있게 하는 **멀티테넌트 SaaS**다. 코드상 서비스명은 "규정관리 시스템", 플랫폼 브랜딩 기본값은 "Policy Manager"(로그인 화면 lockup 이미지 경로 등에는 "veda/astrum" 명칭이 남아 있어 정식 서비스명 확정 필요 — [기술부채 대장](../13_기술부채대장/기술부채_대장.md) 참고).

## 2. 목적

- 사내 규정을 문서(워드/한글 파일)가 아닌 구조화된 데이터(장·조·항·목)로 관리해 검색·개정 이력 추적·양식 통일을 가능하게 함
- 고객사(테넌트)별 브랜딩과 서비스 자체 브랜딩을 분리해 화이트라벨에 가까운 사용 경험 제공
- 플랜(Starter/Pro/Enterprise) 차등화로 SaaS 수익 모델 확보

## 3. 타깃 고객 (미정 — 대표 확인 필요)

코드상 확인되는 사실: 규정 코드/제목/부서/분류/개정일 등 국내 기업·기관의 사내 규정 관리 방식을 전제로 설계됨 (조·항·목 표기, 판례/법령/규칙 참조 태그). 구체적 타깃 업종·기업 규모·영업 채널은 문서화된 바 없음.

## 4. 범위

### 포함
- 규정 CRUD, 조·항·목 계층 편집, 버전 워크플로(초안→검토→시행→폐지)
- 통합검색, 출력 템플릿(인쇄/전문 렌더링), 알림(팀 단위 개정 알림)
- 규정 가져오기(TXT/DOCX/PDF), 멀티테넌시, 역할 기반 접근 제어(admin/editor/viewer)
- 플랜별 기능 제한 및 mock 결제

### 제외 (현재 미구현 — [화면설계서](../11_화면설계서/화면설계서.md) 13절, [FeatureList](../../VEDA_FeatureList.docx) 14절 참고)
- 실제 PG 연동 결제 (mock 프로바이더만 동작)
- 법령정보센터 수준 부가 기능(3단비교, 신구법비교, 법령체계표, 음성·점자 지원 등) — UI에 버튼만 존재, disabled
- 감사 로그 UI, 관리자 벌크 임포트 UI, PDF 파싱(regulation-parse) UI — 백엔드 API만 존재
- 자동 테스트, CI 파이프라인

## 5. 플랜(요금제) 구성 — 코드 기준

| 플랜 | 규정 개수 상한 | 사용자 수 상한 | 주요 차등 기능 |
|---|---|---|---|
| Starter | 5 | 10 | 템플릿(양식) 관리 비활성, 브랜딩 편집 불가. ~~팀원 초대 불가~~ → **코드는 막지 않는다**(상한 10명까지 허용). 이 표의 "초대 불가"와 "사용자 상한 10"이 서로 모순이다 — 결정 대기 D-07 |
| Pro | 10,000 | 50 | 브랜딩 편집, 출력 템플릿 basic 빌더, 팀원 초대, 알림 팀 관리 |
| Enterprise | 1,000,000(사실상 무제한) | 1,000,000(사실상 무제한) | 출력 템플릿 HTML/CSS 자유 편집, API 연동 안내 |

(상한 두 칸은 `apps/api/src/common/plan-limits.ts` 기준. **"주요 차등 기능" 칸은 코드와 대조되지 않은 채 유지돼 왔다** — 팀원 초대 항목이 실제와 달랐다. 실제 판매 가격은 미정 — 대표 확인 필요.)
