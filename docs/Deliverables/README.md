# Deliverables

policy_manager 프로젝트 문서 산출물 폴더입니다. 대표·개발자1·개발PM(본인)이 함께 개발하는 소규모 구조라 부서별 작성/주관/자문/검수 역할 구분은 두지 않고, "문서 기준으로 개발한다"는 원칙만 적용합니다. 문서별 상태만 체크하세요.

## 폴더 규칙

- 폴더 최상위에는 **최신 문서 파일만** 둡니다. (예: `프로젝트기획서.md`)
- 지난 버전은 같은 폴더 안 **`구버전/`** 하위 폴더로 옮깁니다.
- 구버전 파일명은 **버전 숫자 접미사**를 붙입니다. (예: `프로젝트기획서_v1.0.md`, `_v1.1.md`)
- 새 버전 작성 시: 기존 최상위 파일 → `구버전/`으로 이동 + 버전 접미사 부여 → 새 파일을 접미사 없이 최상위에 배치.

```
01_프로젝트기획서/
  프로젝트기획서.md          <- 최신본
  구버전/
    프로젝트기획서_v1.0.md
```

## 참고

- `docs/` 최상위의 기존 `v1.md`, `v2.md`, `v3.md`, `policy_manager_개발정의서.docx`, `VEDA_FeatureList.docx`는 그대로 유지됩니다 (이번 재구성 대상 아님). 각 문서 작성 시 개발정의서·FeatureList를 근거로 참조했습니다.
- 06(README), 07(.env.example)은 실제 파일이 저장소 루트에 있어야 동작하므로 폴더에는 이력/참조만 두고 파일 본체는 루트에 유지합니다.
- 각 문서 중 사업적 의사결정이 필요한 부분(서비스명·가격·타깃·git 전략 등)은 본문에 "미정"으로 표시해 두었으니 확정 시 갱신하세요.
