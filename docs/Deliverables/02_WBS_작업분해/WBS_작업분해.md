## WP8. 법령 개정 연계 (2026-09-21 신설) — **남은 개발의 거의 전부**

근거: 특허 명세서 `26PD0271KR_명세서_수정안rev1.docx`. 설계는 [18_법령개정연계_설계](../18_법령개정연계_설계/법령개정연계_설계안.md), 요구사항은 [03_SRS 12절](../03_SRS_요구사항명세/SRS_요구사항명세.md), 아키텍처는 [04_시스템아키텍처 15절](../04_시스템아키텍처/시스템아키텍처.html).

청구항 1의 7단계 중 **빠진 것은 하나의 사슬**이다 — 연결 → 감지 → 영향분석 → 후보생성.
나머지(파싱·시점조회·비교·승인 워크플로·감사로그·테넌트 격리)는 이미 만들어 둔 것 위에 얹힌다.

**순서를 건너뛸 수 없다.** 1단계(연결)가 없으면 2~4단계가 성립하지 않는다.

### 1단계 — 법령 엔티티 + 법령 관계 정보
- [x] `LawSource`/`Law`/`LawArticle` 스키마 + 법제처 MST로 법령 등록 (T-100, 9/25)
- [x] `LawLink` — 법령조항 ↔ 사내 조문 연결. 관계 유형·근거 문구·신뢰도·**확정 상태** (T-101, 9/25)
- [x] 연결 화면 — 조문 상세에서 "걸린 법", 법령 상세에서 "영향받는 우리 조문" (T-102, 9/26)

> **단독으로 쓸모 있다**: 자유 텍스트 메모(`relatedLawNote`)가 **추적 가능한 연결**이 된다.
> 후보 생성이 없어도 "이 법이 바뀌면 어디가 영향받나"를 사람이 직접 볼 수 있다.

### 2단계 — 변경 감지

- [x] `POST /admin/law-sync/run` (cron 호출) + 동기화 이력. **실패를 "개정 없음"과 구별해 기록** (T-104, 10/7)
