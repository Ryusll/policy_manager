## 개발 단계 (2026-07-29 대표님 지시 반영)

대표님이 전달한 우선순위 피드백(P0/P1/P2, 11개 항목)을 기존 백로그와 통합해 **5단계**로 재편했다. 위에서 아래 순서로 진행한다.

| 단계 | 이름 | 목표 | 근거 |
|---|---|---|---|
| **S0** | 빌드 기반 선행 | 클린 체크아웃에서 빌드·배포가 재현됨 | 스모크 테스트 실측(대표님 목록에 없던 항목) |
| **S1** | 계약 확정 (대표 P0) | 토큰 계약·파서 연결고리·sanitizer — **법제처 연동의 설계 전제조건** | 대표님 P0 |
| **S2** | 법제처 API 연동 (대표 P1) | 외부 법령 데이터를 조·항·목으로 수용 | 대표님 P1 |
| **S3** | 연동 마무리·안정화 (대표 P2) | 보안/안정성 부채 정리 | 대표님 P2 |
| **S4** | 잔여 기능격차 | SRS 14절 미구현 항목 정리 | 기존 백로그 |
| **S7** | **법령 개정 연계** | **법령 개정 → 영향 조문 → 개정 후보 추천 → 사람 승인.** 제품의 핵심 기능이자 남은 개발의 거의 전부 | **특허 명세서 `26PD0271KR`** (2026-09-21 대표 확인) |

> **순서 근거(대표님 문서)**: S1을 먼저 하는 이유는 토큰 계약과 파서-구조 연동이 법제처 연동의 전제조건이기 때문. 계약 없이 외부 데이터를 붙이면 재작업이 발생한다. S2는 붙는 순간 S1-2의 자동매핑 문제를 상당 부분 흡수하는 시너지가 있어 직후 착수가 효율적.

### ⚠️ 착수 전 정정사항 (코드 실측 결과)

대표님 문서는 v1~v3·개발정의서 기반 분석이라 실제 코드와 3가지 차이가 있다. 작업 범위에 반영했다.

| 문서 서술 | 코드 실측 | 영향 |
|---|---|---|
| 지원 토큰에 `{{article.number}}` 포함 | **미지원**. 최상위 토큰은 `tenant.name`/`policy.title`/`policy.code`/`today`/`revisionDate`/`effectiveDate`/`content`/`logo`뿐. 조문은 `{{content}}` 안에 렌더됨 | S1-1에서 실제 토큰만 명세 |
| `docs/template-feature-test-checklist.md`에 수동 QA 체크리스트 존재 | **파일 없음** | S3-10 E2E 작업 시 체크리스트도 신규 작성 필요 |
| 마이그레이션 "총 6건 이상 누적" | 실제 **12건**, 단 baseline 부재로 `migrate deploy` 실패 → `db push` 폴백 | S0-3 유지 |

**추가 발견(실제 버그)**: 설정 화면 템플릿 미리보기가 `revisionDate`·`effectiveDate`를 데이터로 넘기지 않아, 해당 토큰을 쓴 템플릿이 **미리보기에서는 빈칸, 실제 규정에서는 정상** 렌더된다. S1-1에서 함께 수정.
