## 2. 로그인 / 회원가입 (LoginPage / RegisterPage / OAuthCallbackPage)

- 이메일+비밀번호 로그인, 조직 slug(기관 코드) 입력. **회원가입 링크는 공개 회원가입이 열린 서버(개발)에서만** 보이고, 운영에서는 "계정이 필요하면 회사 관리자에게 요청하세요" 안내(`GET /auth/options`, T-122). 고객사는 아스트룸이 통합 관리자 콘솔에서 개설한다
- **첫 로그인 비밀번호 변경**(`ForcePasswordChangePage`, T-122): 관리자·아스트룸이 정해 준 비밀번호로 들어오면 앱 대신 이 화면만 보인다(받은 비밀번호·새 비밀번호·확인, 로그아웃). 바꾸면 로그인 화면으로 돌아가 새 비밀번호로 다시 들어온다. 다른 화면 주소로 가도 이 화면이 나온다
- Google OAuth 로그인 버튼 (`GET /auth/google` 리다이렉트 → `OAuthCallbackPage`에서 토큰 수신)
- 헤더: 테넌트 브랜딩(로고 있으면 이미지, 없으면 BrandBadge)

## 3. 대시보드 (DashboardPage)

- PageHeader + 통합검색 바로가기
- KPI stat-card 4개: 전체 규정 수 / 시행중 / 비활성 / 권한(역할 표시)
- 최근 수정 규정 6건 리스트 — 부서·분류 배지, 시행 상태 배지
- 데이터 없을 때 EmptyState + 규정 등록 CTA

## 4. 규정 목록 (PoliciesPage)

- PageHeader + 규정 등록 버튼
- 등록 탭: 기본 등록 / 기존 규정 가져오기(Import Wizard)
- 담당 부서·규정 분류 메타데이터 입력 필드
- 검색 + 부서/분류 필터, 목록은 `gov-table` 스타일
- 등록 성공 시 토스트 알림
- 하단: 가져오기 이력(PolicyImportLog) 목록

### 4.1 규정 가져오기(Import Wizard)
- 파싱 프로필: 혼합형 / 한국형 / 영문형
- 입력 방식: 파일 업로드(TXT/DOCX/PDF) 또는 텍스트 붙여넣기
- 실시간 미리보기: 인식된 장 수 / 조문 수
- 고급 옵션(접이식): 구분 모드(auto/blank_block/line_each/delimiter/markdown), 원문 정제(공백·머릿글 제거, 따옴표 통일, `**굵게**` 래핑)
- 등록 시 번호 자동 재정렬, 빈 조문 자동 제거
- 「항·목 자동 인식」(기본 ON): 원문의 ①②… → 항, `1. 2. …` → 목으로 인식해 계층까지 등록. 등록 전 인식 개수를 안내하며, 패턴이 없으면 조 단위로만 등록 (2026-07-30, T-51)
- 원문에 장 표기가 없으면 **임의의 "제1장 총칙"을 만들지 않고** 숨김 장에 담는다 (2026-08-02, SRS POLICY-6)

## 5. 규정 상세 (PolicyDetailPage) — 핵심 화면

### 5.1 공통
- 로딩: LoadingBlock / 규정 없음: EmptyState
- Breadcrumb(페이지 자체 구현, 전역 breadcrumb 숨김): 규정 목록 > {규정명} · {전문 보기|분절 보기}

### 5.2 좌측 사이드바 3탭
| 탭 | 기능 |
|---|---|
| 본문·목차 | 목차(TOC) 트리 + 조문 검색 필터 |
| 연혁 | 조문별 현재 게시(published) 버전 스냅샷 |
| 부칙·별표 | PolicyAppendix CRUD (부칙/별표/서식) |

### 5.3 목차(TOC) 패널
- 보이기/숨기기, 고정 모드(sessionStorage 저장)
- 조문번호·제목 필터 검색
- 계층 표시: 장 > **절(선택)** > 조(제N조) > 항(①②…) > 목(1. 2. …)
- 절은 선택 계층이라 한 장 안에 "절에 속하지 않는 조"와 "절에 속한 조"가 공존한다. 절 미소속 조를 먼저 보이고, 이어서 `제N절` 헤더 + 소속 조문을 번호순으로 표시
- 장 블록마다 「+ 절 추가」 버튼, 절 헤더에 「삭제」(조문은 보존되고 절 연결만 해제), 절별 「제N절에 조 추가」
- 조 그룹별 「+ 제N조 항 추가」, 「+ 조 추가」 버튼 — 항 추가 시 다음 항 번호 자동 제안
- **장을 만들지 않고 조부터 추가 가능**: 장 없이 「조 추가」를 누르면 숨김 장이 자동 생성되어 조가 담기고, 화면·인쇄에는 장 제목이 보이지 않는다
- `suppressHeader` 장은 장 제목 숨기고 조문만 표시

### 5.4 본문 영역
- **전문 보기**: 규정 전체를 한 화면에 렌더 (인쇄용 레이아웃과 동일 계열)
- **분절 보기**: 조문 단위 선택·편집, 우측에 판·법·규 배지 및 연관 항목 미리보기 패널
- 버전 워크플로 UI: 초안 작성 → 검토 요청 → 시행 승인(승인 사유 필수, 기존 published는 자동 archived) · 반려·폐지도 화면에서 처리(T-10)
- 신구 버전 비교(diff): 줄 단위 / 단어 단위
- 규정 개정일·시행일 편집 + 개정 알림 수신자 설정(팀/개인)
- 전체화면 보기, 인쇄(window.print, 선택 템플릿 렌더), 전문 `.txt` 다운로드, 주소 복사
- **본문 글자 크기**: 도구줄 `가− / 100% / 가+` (90·100·110·125·150%). 본문만 커지고 목차·도구줄은 그대로. 선택은 브라우저에 유지되며 **인쇄물·PDF·HWPX 는 영향받지 않는다**(T-75)
- **규정 간 비교**: 같은 기관의 다른 규정을 골라 조문을 나란히 대조. 조·항·목 번호로 맞대므로 **번호는 같은데 제목이 다른 줄에 「제목 불일치」 경고**가 붙는다. 「다른 조문만」 필터 기본 켜짐 (T-91)
- 조문 코멘트: 작성 + 처리완료/미처리 토글
- **첨부파일 모달**: 목록(파일명·크기) + 다운로드 링크. admin·editor 는 「파일 추가」와 행별 「삭제」(확인 대화상자에서 파일명을 보여 준다). viewer 는 목록·다운로드만.
  - 목록에 뜨는 이름은 **올린 그대로의 이름**이다. 디스크 저장명은 따로 있고(경로 탈출 방어 때문에 ASCII 로 제한), 원래 이름은 그 안에 실어 되돌린다(T-90)
  - 업로드·삭제는 감사 로그에 남는다(`policy.file.upload` / `policy.file.delete`)
- 외부 링크: 표준국어대사전, Google 법령 검색
- 조·항·목 구조 편집 패널: 조 번호·항·목 번호·제목 수정 → `PUT /policies/:id/chapters/:chapterId/articles/:articleId`
- 조문 추가 모달: 판·법·규 체크 + 근거 메모, 초기 본문 입력 시 draft v1 버전 자동 생성

## 8. 설정 (SettingsPage)

좌측 탭 구조:

| 탭 | 기능 |
|---|---|
| UI | 테마 프리셋(forest/ocean/slate/wine) + 커스텀 Primary/Accent 색상, 브랜드 마크(1~2자)·로고 업로드·크기, 헤더/로그인 미리보기 (Pro+ 플랜 전용) |
| Invite(팀) | 팀원 초대(admin이 이메일·초기 비밀번호·역할로 생성 — **플랜 무관**, T-122/D-07 정리. 초기 비밀번호는 직원이 첫 로그인 때 바꾼다는 안내), 개정 알림 수신 팀(NotificationGroup) CRUD |
| 구성원 관리 | **admin 이 같은 조직 구성원의 이름·이메일·역할을 수정**(행의 `수정` → 인라인 폼 → 저장). **플랜과 무관하게 admin 이면 활성**(`Invite` 탭과 같다 — T-122). 본인 행에 `나` 표시, **마지막 admin 은 역할 선택이 잠기고 이유를 안내**한다. 본인의 admin 역할을 내릴 때는 확인창을 띄우고, 저장 즉시 관리자 전용 메뉴가 사라진다. 본인을 뺀 각 행에 `비밀번호 재설정`(임시 비밀번호 입력, 8자 이상) (T-113·T-114) |
| 양식 관리 | PolicyTemplate 편집·미리보기 — Starter는 비활성, Pro는 basic 빌더, Enterprise는 HTML/CSS 자유 편집 |

## 9-1. 법령 관리 (LawsPage · LawDetailPage) — S7

- **목록**(`/laws`): 법제처에서 등록한 법령(테넌트 공용). "마지막 확인" + `확인 실패` 배지(T-104). admin·editor 에게는 맨 위에 **최근 법령 변경** 카드(T-105) — 기본은 "우리 회사 조문에 걸린 변경만". 행마다 변경 유형(신설·변경·삭제), 조문 표기, 법령 시행일, 감지 경로·날짜, `우리 조문 N`(확정 연결)·`확인 필요 M`(추천 연결). 누르면 법령 상세의 그 변경으로 이동(`?change=`)
- **상세**(`/laws/:id`): 머리말(구분·번호·시행일·조문 수·원문 링크·마지막 개정 확인·실패 안내) → **개정 내역** 카드(T-105, admin·editor): 이 법령의 변경 목록, 펼치면 `LawImpactPanel` — 변경 전·후 문구, 기준일과 그 의미, 추천 연결 안내, 규정별로 묶은 영향 조문(조문 링크 `/policies/:id#제N조…`·관계 유형·근거 문구·**지금 기준 본문** v번호·시행일, 시행 전이면 "개정 초안을 만들 수 없음", 시행일이 기록되지 않은 가져온 규정이면 "규정 화면에서 시행일을 넣으면 만들 수 있음" + 규정 링크), 조문이 사라진 변경은 사유. **개정 후보**(T-106): 기준 본문이 있는 조문이 하나라도 있으면 `개정 후보 만들기` 버튼(결과는 토스트 — 새 후보·이미 있던 후보·건너뛴 조문 수). 후보가 있는 조문 아래에 `AmendmentCandidatePreview` — 상태·신뢰도(높음/보통/낮음) 배지와 검토 사유 배지(직접 작성 필요·대응 위치 모호 등), 기준 본문 대비 **삭제는 취소선·추가는 밑줄**, `근거 · 기준값 변경 15일 → 20일` 같은 적용 규칙 줄, `반영 못 한 법령 변경 · "…" → "…" — 이유` 줄. 반영한 것이 없으면 본문 대신 "직접 고쳐야 합니다" 안내. 후보를 만든 뒤 기준 본문이 바뀌었으면 그 안내. 미리보기는 읽기 전용이고 `검토 화면에서 보기`(고친 후보면 판 번호)로 개정 검토 상세에 간다(T-107). 반영 여부는 지금 판으로 판단한다 — 사람이 고친 후보는 "직접 고쳐야 합니다" 대신 바뀐 본문을 보인다 → 아래 조·항·호 트리와 선택한 조항의 "영향받는 우리 조문"(T-102)

## 9-2. 개정 검토 (AmendmentsPage · AmendmentDetailPage) — S7, T-107

- **메뉴**: 헤더 nav `개정 검토`(법령 관리 다음) — admin·editor 에게만 보인다.
- **목록**(`/amendments`): 상태 탭(처리할 것 = 작성·검토 / 작성 중 / 검토 중 / 승인됨 / 반려됨 / 전체, 기본 처리할 것) + 규정·규정 시행 여부 필터. 행: 규정·조문 표기·조문 제목·상태 배지, `비활성 규정`·`기준 본문 바뀜`·`직접 작성 필요`·`근거 없는 변경 N` 배지, 법령 변경(법령명·조항·법령 시행일)·생성 시 신뢰도·판 번호·만든 사람(자동 생성)·날짜. 30건씩 페이지.
- **상세**(`/amendments/:id`): 머리말(← 개정 검토, 규정·조문 링크, 상태, 생성 시 신뢰도·검토 사유·`직접 작성 필요`·`근거 없는 변경 N`·`사람이 고침` 배지, 법령 변경 링크(법령 상세의 그 변경)·법령 시행일·기준일·만든 사람) → 경고: 기준 본문이 그 사이 바뀌었으면 "후보를 만든 뒤 이 조문이 개정됐습니다"와 `지금 기준 본문 보기`·`지금 기준 본문으로 다시 만들기`(그 조문만, 새 후보로 이동), 검토 중이면 요청(판·요청자·시각·사유) → **3단**(넓은 화면): ① 기준 본문(제1 조문 v·시행일) ② 개정 후보(판 N) — `AmendmentDiffView`: 바뀐 곳마다 누를 수 있고 삭제 취소선·추가 밑줄, 근거 없는 변경은 점선 테두리 ③ 변경 근거 — 누른 변경의 적용 규칙·반영한 법령 변경·연결(관계 유형·확정·적용 범위·근거 문구·경로), 근거가 없으면 "근거 없음 — 사람이 고친 부분…검토해야 합니다". 아무것도 안 눌렀으면 법령 변경별 반영 결과(반영함(규칙) / 반영 못 함: 이유). 좁은 화면은 위아래로 쌓인다 → 법령 변경(전·후) → **손질·검토 요청**(작성·검토 상태): `후보 손질` → 본문 편집 + 수정 사유(필수) → `새 판으로 저장`(검토 중이면 "작성으로 돌아가 다시 요청해야 한다" 안내). 그 사이 누가 바꿨으면(409) 화면은 최신 판으로 바뀌고 고친 내용은 입력란에 그대로 남는다. 작성 상태면 `판 N로 검토 요청` — 본문이 기준 본문과 같으면 "개정이 필요 없다고 보는 이유"(필수), 기준 본문이 바뀐 후보면 경고 → **이력**(판 생성·손질과 사유, 직전 판 대비 펼쳐 보기, 검토 요청·요청 취소) → 같은 법령 변경·조문의 다른 후보 링크.
- **승인·반려**(T-108, 관리자·검토 중일 때만 — 편집자에게는 보이지 않는다): `승인 · 반려 (판 N)` 카드 — 사내 규정 시행일(달력, 오늘 이전 선택 불가, 기본값 없음, "참고: 법령 시행일 …"), 개정 사유(필수, `사유 초안 넣기`로 "법령명 조항 개정 반영" 채움), 법령 시행일보다 이르면 "이르게 시행하는 이유"(필수) 칸이 나타난다. 날짜를 고르면 "새 버전이 발행되고 그날부터 시행 — 그날 전까지 시점 조회는 지금 본문" 요약. `승인 — 후속 버전 발행`. 막히면(409) 빨간 안내에 원인과 날짜·버전이 나오고, 기준이 어긋난 경우 `그 날짜 기준으로 다시 만들기`(새 후보로 이동), 시행일 미기록이면 규정 화면 링크. 아래 반려 사유(필수) + `반려 — 발행하지 않음`. 승인 뒤: 초록 배너 "승인됨 — vN 발행 · 시행 날짜(시행 예정) · 승인자 · 시각 · 개정 사유 · 규정에서 보기", 승인·손질 카드는 사라진다. 반려 뒤: 장미색 배너 "반려됨 — 판 · 반려자 · 시각 · 반려 사유 · 고치면 작성으로", 손질은 남는다. 이력에 "승인 — 후속 버전 발행"·"반려"·"반려 뒤 손질 — 작성으로".
