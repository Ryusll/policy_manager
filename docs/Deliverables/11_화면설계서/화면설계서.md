## 2. 로그인 / 회원가입 (LoginPage / RegisterPage)

- 이메일+비밀번호 로그인, 조직 slug(기관 코드) 입력. **회원가입 링크는 공개 회원가입이 열린 서버(개발)에서만** 보이고, 운영에서는 "계정이 필요하면 회사 관리자에게 요청하세요" 안내(`GET /auth/options`, T-122). 고객사는 아스트룸이 통합 관리자 콘솔에서 개설한다
- **첫 로그인 비밀번호 변경**(`ForcePasswordChangePage`, T-122): 관리자·아스트룸이 정해 준 비밀번호로 들어오면 앱 대신 이 화면만 보인다(받은 비밀번호·새 비밀번호·확인, 로그아웃). 바꾸면 로그인 화면으로 돌아가 새 비밀번호로 다시 들어온다. 다른 화면 주소로 가도 이 화면이 나온다
- **자동 로그인** 체크박스(기본 꺼짐, T-137): 켜면 30일 동안 로그인 유지(브라우저를 껐다 켜도), 끄면 브라우저를 닫을 때 로그아웃. 안내 "30일 동안 로그인 상태를 유지합니다. 여러 사람이 쓰는 PC에서는 켜지 마세요." 같은 브라우저의 탭들은 로그인·갱신·로그아웃을 함께 따른다
- ~~Google OAuth 로그인 버튼~~ → **삭제(T-136)**. B2B 계정 체계라 로그인은 이메일·비밀번호 하나다. 비밀번호 없는 예전 구글 계정은 "비밀번호가 설정되지 않은 계정입니다. 회사 관리자에게 비밀번호 재설정을 요청하세요." 안내
- 헤더: 테넌트 브랜딩(로고 있으면 이미지, 없으면 BrandBadge)

- PageHeader + 규정 등록 버튼

### 4.1 규정 가져오기(Import Wizard)
- 파싱 프로필: 혼합형 / 한국형 / 영문형
- 입력 방식: 파일 업로드(TXT/DOCX/PDF) 또는 텍스트 붙여넣기
- 실시간 미리보기: 인식된 장 수 / 조문 수
- 고급 옵션(접이식): 구분 모드(auto/blank_block/line_each/delimiter/markdown), 원문 정제(공백·머릿글 제거, 따옴표 통일, `**굵게**` 래핑)
- 등록 시 번호 자동 재정렬, 빈 조문 자동 제거
- `가져와서 등록`은 한 번에 저장된다(T-135, `POST /policies/import` 한 요청) — 실패하면 규정이 아예 생기지 않는다(예전엔 장·조문을 하나씩 보내 반쪽 규정이 남을 수 있었다). 관리자는 시행일(필수)로 바로 시행, 편집자는 초안으로 남는다
- 「항·목 자동 인식」(기본 ON): 원문의 ①②… → 항, `1. 2. …` → 목으로 인식해 계층까지 등록. 등록 전 인식 개수를 안내하며, 패턴이 없으면 조 단위로만 등록 (2026-07-30, T-51)
- 원문에 장 표기가 없으면 **임의의 "제1장 총칙"을 만들지 않고** 숨김 장에 담는다 (2026-08-02, SRS POLICY-6)

### 4.2 규정 가져오기 — 서버 파싱 (PolicyImportPage, `/policies/import`)
- 1단계 원문 가져오기(PDF 업로드 / 법제처에서 가져오기 / JSON 일괄 등록) → 2단계 조항 트리 미리보기·수정 → 3단계는 둘 중 하나:
  - **새 규정으로 등록** — 코드·제목·시행일(필수)·설명 → `조항 N건으로 규정 만들기`. 한 번에 저장된다(T-135) — 실패하면 아무것도 생기지 않고(원문 PDF 도 남는다) 같은 원문으로 다시 누르면 된다. 이미 쓴 원문·그 사이 바뀐 미리보기·첨부 실패는 안내 문구로 알린다
  - **기존 규정에 다시 가져오기**(T-110 재파싱) — `대상 규정` 선택(파일 이름이 아니라 어느 규정의 원문인지를 고른다, 문서 제목과 같은 규정이 있으면 미리 골라 둠)
    → `조항 N건을 기존 조문과 비교` → 고친 트리가 있으면 먼저 저장하고 재파싱 검토 화면으로. 규정 상세의 `원문 다시 가져오기`는 `?target=규정id` 로 이 모드를 골라 둔 채 연다.

### 4.3 재파싱 검토 (ReparseReviewPage, `/policies/:id/reparse/:reviewId`) — T-110 ①
- 머리말 `재파싱 검토` · 규정명 · 원문 이름 · 비교 시각, `다시 비교`(같은 원문으로 다시 — 정한 결정은 같은 항목이면 옮겨 옴)·`규정으로`.
- 요약: 종류별 배지(그대로·옮김·본문 바뀜·판정 보류·새 조문 후보·원문에 없음), `결정 남음 N건 · 삭제 여부 미결 N건`, 초안·검토 중 버전이 있는 조문 수,
  "부칙·별표 N건은 이번 비교에서 뺐습니다", 판정·정규화 규칙 버전. 장 단위 변경(번호 바뀜·제목 바뀜·새 장·원문에 없는 장).
- 묶음(확인할 것이 먼저): **확인할 것**(본문 바뀜·판정 보류·추천하지 않은 옮김 — `본문 바뀐 N건 모두 개정으로`) / **옮김** / **새 조문 후보** / **원문에 없음 — 삭제 여부 확인** / **그대로**(접힘).
- 항목: 종류 배지·번호·제목, 옮겼으면 "← 기존 제N조(·제N장에서)", 조 제목이 바뀌었으면 그 사실, 판정 근거 배지, 초안·검토 중 버전 있음. 본문 바뀜은 낱말 단위 비교(지운 낱말
  취소선, 더한 낱말 초록)와 비교 대상(v번호·시행일), 띄어쓰기로 맺은 옮김은 "같은 조문인지 확인하세요". 판정 보류는 후보 라디오(폐지된 조문 표시), 새 조문 후보는
  "원문에 없는 기존 조문에 잇기" 선택(이은 조문은 "이어졌습니다"). 결정 버튼(개정으로·새 조문으로·옮김으로·보류·그대로 둠·폐지 — 폐지는 관리자), 정한 시각 / "미리 골라 둠".
- 비교 뒤 규정이 바뀌었거나 원문 트리를 고쳤으면 노란 안내와 `다시 비교`. 지나간 검토는 결정할 수 없다는 안내.
- **반영과 묶음 승인**(T-110 ②) 카드 — 상태 배지(결정 중·반영함 — 묶음 검토 요청 전·묶음 검토 중·승인함·반려함).
  - 결정 중: `반영 — 묶음 초안 만들기`(결정이 남거나 낡았으면 꺼짐). "기존 조문의 묶음 초안만 만들고 지금 본문·번호는 그대로, 새 조문·새 장은 승인 때".
  - 반영함: `묶음 초안 N건 · 새 조문 N건(승인 때 만듦) · 새 장 N개 · 장 번호·제목 변경 N개 · 폐지 N건`, `묶음 검토 요청`, 관리자는 `묶음 반려`(사유).
  - 묶음 검토 중: 관리자는 사내 규정 시행일(기본 오늘)·개정 사유 → `묶음 승인 — 후속 버전 발행`, 시행일의 뜻(그 전 날짜는 옛 번호, 미래면 폐지는 미결) 안내.
  - 승인함: `날짜부터 시행 · 사유`. 반려함: 사유와 `같은 원문으로 다시 비교`.
  - 항목마다 결과 배지(개정·자리 옮김·장 변경 — 초안/검토 중/시행 vN, 새 조문 — 승인 때 만듦/만듦, 조 제목 행 옮김, 폐지 — 승인 때/폐지함(날짜)/미결, 보류, 유지).
    승인·반려 뒤 원문에 없는 조문은 `유지로 닫기`·`오늘 폐지`(관리자). 반영·검토 요청 뒤 규정이 바뀌면 "더 진행할 수 없음 — 반려하고 다시 비교" 안내.
- 규정 상세(5.4): 도구줄 `원문 다시 가져오기`(관리자·편집자), 진행 중인 검토가 있으면 파란 안내 — 결정 중이면 "이 규정과 비교해 둔 원문이 있습니다 — 파일명 · 결정 남음 N건", 반영함이면 "묶음 초안을 만들었습니다 — 묶음 검토 요청 전", 묶음 검토 중이면 "관리자 승인 대기", 승인·반려 뒤엔 삭제 여부를 정하지 않은 조문 수 — + `재파싱 검토 보기`. 버전 카드: 재파싱 묶음의 버전은 단건 `검토 요청`·`시행 승인`·`반려` 대신 `재파싱 묶음` 링크, 제안 계층이 있으면 "제안 계층: 제N조(제목) — 승인한 시행일부터 이 자리로 옮깁니다"(T-110 ②).

## 5. 규정 상세 (PolicyDetailPage) — 핵심 화면

### 5.1 공통
- 로딩: LoadingBlock / 규정 없음: EmptyState
- Breadcrumb(페이지 자체 구현, 전역 breadcrumb 숨김): 규정 목록 > {규정명} · {전문 보기|분절 보기}

### 5.2 좌측 사이드바 3탭
| 탭 | 기능 |
|---|---|
| 본문·목차 | 목차(TOC) 트리 + 조문 검색 필터 |
| 연혁 | 조문별 현재 게시(published) 버전 스냅샷 |
| 부칙·별표 | PolicyAppendix CRUD (부칙/별표/서식) |

### 5.3 목차(TOC) 패널
- 보이기/숨기기, 고정 모드(sessionStorage 저장)
- 조문번호·제목 필터 검색
- 계층 표시: 장 > **절(선택)** > 조(제N조) > 항(①②…) > 목(1. 2. …)
- 절은 선택 계층이라 한 장 안에 "절에 속하지 않는 조"와 "절에 속한 조"가 공존한다. 절 미소속 조를 먼저 보이고, 이어서 `제N절` 헤더 + 소속 조문을 번호순으로 표시
- 장 블록마다 「+ 절 추가」 버튼, 절 헤더에 「삭제」(조문은 보존되고 절 연결만 해제), 절별 「제N절에 조 추가」
- 조 그룹별 「+ 제N조 항 추가」, 「+ 조 추가」 버튼 — 항 추가 시 다음 항 번호 자동 제안
- **장을 만들지 않고 조부터 추가 가능**: 장 없이 「조 추가」를 누르면 숨김 장이 자동 생성되어 조가 담기고, 화면·인쇄에는 장 제목이 보이지 않는다
- `suppressHeader` 장은 장 제목 숨기고 조문만 표시

### 5.4 본문 영역
- **전문 보기**: 규정 전체를 한 화면에 렌더 (인쇄용 레이아웃과 동일 계열)
- **분절 보기**: 조문 단위 선택·편집, 우측에 판·법·규 배지 및 연관 항목 미리보기 패널
- 버전 워크플로 UI: 초안 작성 → 검토 요청 → 시행 승인(승인 사유 필수, 기존 published는 자동 archived) · 반려·폐지도 화면에서 처리(T-10)
  - **폐지**(T-126): 확인 창에 "오늘(날짜)부터 이 조문은 시행에서 빠집니다 — 그날부터의 시점 조회·신구조문대비표·법령 영향 분석에 나오지 않고, 그 전 날짜에는 지금 본문이 그대로", "되돌릴 수 없고, 다시 시행하려면 새 버전을 오늘이나 그 뒤 시행일로 승인". 날짜는 고르지 않는다. 거부되면(시행일 없음·시행 전·오늘 뒤 시행 버전 등) 서버 안내를 창에 보인다. 버전 카드에 `시행 날짜`·`날짜 폐지`, 상태 배지는 폐지한 버전만 "폐지"이고 새 버전에 밀려 내려간 버전은 "이전 버전"(버전 비교 목록·개정 이력 타임라인도 같다)
  - **변수 연결**(T-109): 시행 중인 버전 카드에 `변수 연결 N`(관리자·편집자, 연결이 있으면 누구나) → 창: 이은 자리를 표시한 본문, 연결 목록(변수·문구·몇 번째 출현·"다시 이어야 함"·`연결 풀기`), 저장된 본문을 그대로 보여 주는 읽기 전용 칸에서 문구를 골라(앞뒤 공백은 빠진다) 변수를 정하고 `연결` — 이미 이은 자리와 겹치면 막는다
  - **날짜 3종**(T-111): 발행 이력(시행 중·이전 버전·폐지) 카드의 머리 아래 한 줄 — `사내 시행일 날짜`(시행 중인데 오늘 뒤면 "(시행 예정)") · `발행 YYYY-MM-DD HH:mm`(한국 시각 — 옛 발행은 "(승인 기록으로 보정)", 기록이 없으면 "기록 없음") · `법령 시행일 날짜 (법령명 조항)`(개정 후보 승인 버전만, 이벤트에 날짜가 없으면 "기록 없음"). 사내 시행일이 더 이르면 노란 `법령보다 조기 시행`. 관리자·편집자에게는 법령명 조항이 법령 상세의 그 변경으로, `승인 사유 보기`(조기 시행일 때)·`개정 후보 보기`가 후보 화면으로 이어진다 — 열람자(조문 주소로 들어와 카드를 볼 때)는 글자만. 머리줄의 "시행 날짜"는 이 줄로 옮겼다. 초안·검토 중 카드에는 없다. 같은 표기를 한 줄 글로 왼쪽 **연혁** 탭(조마다 시행본 — 예전 작성일 대신)과 오른쪽 **개정 이력 타임라인**(초안·검토 중은 "작성 날짜")에 쓴다
  - **검토 요청**(T-109): 초안의 변수 표식이 오늘 값으로 바뀌어 카드에 실제 문구가 보인다. 값을 정할 수 없으면 "값을 정할 수 없는 변수 표식이 있습니다 — {{KEY}}(표시명) — 까닭" 알림
  - **시행 승인 창**: 서버가 거부한 까닭을 창에 보인다(폐지일보다 이른 시행일(T-126), 그 시행일의 변수 값이 검토 요청 때와 다름(T-109) 등)
  - **시점 조회**(T-126): 그날 폐지돼 있던 조문은 본문에서 빼고 빨간 안내 "그날 폐지돼 있어 뺀 조문 N개: 제N조(날짜 폐지)…"(5개까지). 개정 시점 목록에 폐지일도 들어간다
- 신구 버전 비교(diff): 줄 단위 / 단어 단위
- 규정 개정일·시행일 편집 + 개정 알림 수신자 설정(팀/개인)
- 전체화면 보기, 인쇄(window.print, 선택 템플릿 렌더), 전문 `.txt` 다운로드, 주소 복사
- **본문 글자 크기**: 도구줄 `가− / 100% / 가+` (90·100·110·125·150%). 본문만 커지고 목차·도구줄은 그대로. 선택은 브라우저에 유지되며 **인쇄물·PDF·HWPX 는 영향받지 않는다**(T-75)
- **규정 간 비교**: 같은 기관의 다른 규정을 골라 조문을 나란히 대조. 조·항·목 번호로 맞대므로 **번호는 같은데 제목이 다른 줄에 「제목 불일치」 경고**가 붙는다. 「다른 조문만」 필터 기본 켜짐 (T-91)
- 조문 코멘트: 작성 + 처리완료/미처리 토글
- **걸린 법**(T-101, 분절 보기 오른쪽 패널, admin·editor): 이 조문에 걸린 법령조항 — 확정·반려·삭제·추가·자동 추천. 근거 문구 아래 회색 `출처 vN · 시행 날짜`(근거 문구가 들어 있던 버전, 초안·검토중이면 괄호로 — 없으면 `출처 버전 없음`)와, 본문에서 찾은 근거 문구가 시행중인 버전 본문에 없으면 호박색 `시행중인 vN에 없는 문구`(출처 버전이 그 뒤 지워졌어도 — 처음부터 본문 밖 문구인 메모 인용·직접 쓴 설명은 알리지 않는다). 시행중인 버전이 없으면(초안뿐·폐지) 알리지 않는다(T-177). 조문의 시행 버전이 바뀌면(승인 등) 목록을 다시 불러온다
- **첨부파일 모달**: 목록(파일명·크기) + 다운로드 링크. admin·editor 는 「파일 추가」와 행별 「삭제」(확인 대화상자에서 파일명을 보여 준다). viewer 는 목록·다운로드만.
  - 목록에 뜨는 이름은 **올린 그대로의 이름**이다. 디스크 저장명은 따로 있고(경로 탈출 방어 때문에 ASCII 로 제한), 원래 이름은 그 안에 실어 되돌린다(T-90)
  - 업로드·삭제는 감사 로그에 남는다(`policy.file.upload` / `policy.file.delete`)
- 외부 링크: 표준국어대사전, Google 법령 검색
- 조·항·목 구조 편집 패널: 조 번호·항·목 번호·제목 수정 → `PUT /policies/:id/chapters/:chapterId/articles/:articleId`
- 조문 추가 모달: 판·법·규 체크 + 근거 메모, 초기 본문 입력 시 draft v1 버전 자동 생성

## 7. 변수 (VariablesPage)

- 변수 목록(T-109): 변수 키(`{{KEY}}`)·표시명(+설명, 값에 기간 겹침·기간 미확정이 있으면 `검토 필요`)·**오늘 값**(없으면 "오늘 맞는 값 없음 / 기간이 겹쳐 고를 수 없음 / 기간 미확정")·연결 수. 등록은 키·표시명·첫 값·첫 값의 시작일(비우면 처음부터)·설명. 편집·등록은 관리자·편집자, 삭제는 관리자
- 행을 펼치면(`값·연결 보기`) **값과 유효기간** — 값마다 "시작 ~ 종료 전날"(비면 처음부터·끝 없음), `오늘 값`·`기간 겹침`·`기간 미확정(옛 기본값)` 배지, 메모, 고치기·지우기·`이 기간으로 확정`. 값 추가(값·시작일·종료일·메모) 뒤 겹치면 "다른 값과 기간이 겹칩니다 — 겹치는 기간에는 이 변수를 쓰지 않습니다" 경고. 아래 **연결된 조문** — 지금 시행 중인 본문에서 이 변수의 값인 자리(규정·조문 링크, "…앞 문맥 [문구] 뒤 문맥…", 옮기지 못한 연결은 "다시 이어야 함 — 까닭")
- 안내: 표식은 검토 요청 때 그날 값으로 바뀐다, 이미 시행 중인 문구는 규정 화면의 "변수 연결"로 잇는다, 값의 유효기간 규칙

## 9-1. 법령 관리 (LawsPage · LawDetailPage) — S7

- **목록**(`/laws`): 법제처에서 등록한 법령(테넌트 공용). "마지막 확인" + `확인 실패` 배지(T-104). admin·editor 에게는 맨 위에 **최근 법령 변경** 카드(T-105) — 기본은 "우리 회사 조문에 걸린 변경만". 행마다 변경 유형(신설·변경·삭제), 조문 표기, 법령 시행일, 감지 경로·날짜, `우리 조문 N`(확정 연결)·`확인 필요 M`(추천 연결). 누르면 법령 상세의 그 변경으로 이동(`?change=`)
- **상세**(`/laws/:id`): 머리말(구분·번호·시행일·조문 수·원문 링크·마지막 개정 확인·실패 안내) → **개정 내역** 카드(T-105, admin·editor): 이 법령의 변경 목록, 펼치면 `LawImpactPanel` — 변경 전·후 문구, 기준일과 그 의미, 추천 연결 안내, 규정별로 묶은 영향 조문(조문 링크 `/policies/:id#제N조…`·관계 유형·근거 문구·**지금 기준 본문** v번호·시행일, 시행 전이면 "개정 초안을 만들 수 없음", 기준일에 폐지돼 있으면 "날짜에 폐지돼 기준일에 시행 중이 아님 — 개정 후보를 만들지 않음"(T-126), 시행일이 기록되지 않은 가져온 규정이면 "규정 화면에서 시행일을 넣으면 만들 수 있음" + 규정 링크), 조문이 사라진 변경은 사유. **개정 후보**(T-106): 기준 본문이 있는 조문이 하나라도 있으면 `개정 후보 만들기` 버튼(결과는 토스트 — 새 후보·이미 있던 후보·건너뛴 조문 수). 후보가 있는 조문 아래에 `AmendmentCandidatePreview` — 상태·신뢰도(높음/보통/낮음) 배지와 검토 사유 배지(직접 작성 필요·대응 위치 모호 등), 기준 본문 대비 **삭제는 취소선·추가는 밑줄**, `근거 · 기준값 변경 15일 → 20일` 같은 적용 규칙 줄, `반영 못 한 법령 변경 · "…" → "…" — 이유` 줄, 변수 줄(`변수 · 담당 부서 운영팀 → 관리팀 (예정 사내 시행일 날짜 값)`, 넣지 않은 자리는 까닭, T-109 ②). 반영한 것이 없으면 본문 대신 "직접 고쳐야 합니다" 안내. 후보를 만든 뒤 기준 본문이 바뀌었으면 그 안내(그 사이 조문이 폐지됐으면 "폐지됐습니다(날짜) — 승인할 수 없으니 검토 화면에서 반려로 닫으세요", T-126). 미리보기는 읽기 전용이고 `검토 화면에서 보기`(고친 후보면 판 번호)로 개정 검토 상세에 간다(T-107). 반영 여부는 지금 판으로 판단한다 — 사람이 고친 후보는 "직접 고쳐야 합니다" 대신 바뀐 본문을 보인다 → 아래 조·항·호 트리와 선택한 조항의 "영향받는 우리 조문"(T-102)
- **조별 시행일 표기(T-144, PAT-06)**: 개정 내역 목록의 줄에 표기가 있는 변경에만 `별도 시행일 표기` 배지, 펼치면 변경 전·후 아래에 호박색 안내 상자 — "이 조(항·호가 속한 조)에 별도 시행일 표기가 있습니다" · "일부는 2027-01-01 시행 (범위 문구)" 또는 "2027-01-01 시행 표기 — 범위 확인 필요" · "영향 분석과 개정 후보의 시행일은 법령(판) 시행일 그대로입니다". 이번 개정으로 표기가 바뀌거나 없어졌으면 "변경 전 표기:" 목록을 덧붙이고, 없어졌으면 머리말이 "이번 개정으로 이 조의(항·호면 "이 항·호가 속한 조의") 별도 시행일 표기가 없어졌습니다"이며 목록 배지는 `시행일 표기 없어짐` 이다. 사라진 조의 이벤트는 머리말이 "이번 개정으로 사라진 조에 있던 별도 시행일 표기입니다"다. 조항 목록에서는 표기가 있는 **조 행**에만 `별도 시행일 표기` 표시(항·호 행은 없음), 조항을 고르면 오른쪽 패널의 본문 아래에 같은 안내 상자(항·호를 고르면 "이 항·호가 속한 조에 …"). 표기가 없으면 아무것도 그리지 않는다.
- **근거 문구의 출처**(T-177): 조문 패널 "영향받는 우리 조문"의 연결마다 근거 문구 아래 `출처 vN · 시행 날짜`, 본문에서 찾은 근거 문구가 그 조문의 시행중인 버전에 없으면 `시행중인 vN에 없는 문구`(규정 상세의 "걸린 법"과 같은 표시)

## 9-2. 개정 검토 (AmendmentsPage · AmendmentDetailPage) — S7, T-107

- **메뉴**: 헤더 nav `개정 검토`(법령 관리 다음) — admin·editor 에게만 보인다.
- **목록**(`/amendments`): 상태 탭(처리할 것 = 작성·검토 / 작성 중 / 검토 중 / 승인됨 / 반려됨 / 전체, 기본 처리할 것) + 규정·규정 시행 여부 필터. 행: 규정·조문 표기·조문 제목·상태 배지, `비활성 규정`·`기준 본문 바뀜`·`직접 작성 필요`·`근거 없는 변경 N` 배지, 법령 변경(법령명·조항·법령 시행일)·생성 시 신뢰도·판 번호·만든 사람(자동 생성)·날짜. 30건씩 페이지.
- **상세**(`/amendments/:id`): 머리말(← 개정 검토, 규정·조문 링크, 상태, 생성 시 신뢰도·검토 사유·`직접 작성 필요`·`근거 없는 변경 N`·`사람이 고침` 배지, 법령 변경 링크(법령 상세의 그 변경)·법령 시행일·기준일·예정 사내 시행일(승인 전이면 "· 미발행", T-111)·만든 사람) → 경고: 기준 본문이 그 사이 바뀌었으면 "후보를 만든 뒤 이 조문이 개정됐습니다"와 `지금 기준 본문 보기`·`지금 기준 본문으로 다시 만들기`(그 조문만, 새 후보로 이동) — 그 사이 조문이 폐지됐으면 "승인할 수 없으니 검토에서 반려로 닫으세요"(다시 만들기 없음, T-126), 검토 중이면 요청(판·요청자·시각·사유) → **3단**(넓은 화면): ① 기준 본문(제1 조문 v·시행일) ② 개정 후보(판 N) — `AmendmentDiffView`: 바뀐 곳마다 누를 수 있고 삭제 취소선·추가 밑줄, 근거 없는 변경은 점선 테두리 ③ 변경 근거 — 누른 변경의 적용 규칙·반영한 법령 변경·연결(관계 유형·확정·적용 범위·근거 문구·경로), 근거가 없으면 "근거 없음 — 사람이 고친 부분…검토해야 합니다". 아무것도 안 눌렀으면 법령 변경별 반영 결과(반영함(규칙) / 반영 못 함: 이유). 좁은 화면은 위아래로 쌓인다 → 법령 변경(전·후) → **손질·검토 요청**(작성·검토 상태): `후보 손질` → 본문 편집 + 수정 사유(필수) → `새 판으로 저장`(검토 중이면 "작성으로 돌아가 다시 요청해야 한다" 안내). 그 사이 누가 바꿨으면(409) 화면은 최신 판으로 바뀌고 고친 내용은 입력란에 그대로 남는다. 작성 상태면 `판 N로 검토 요청` — 본문이 기준 본문과 같으면 "개정이 필요 없다고 보는 이유"(필수), 기준 본문이 바뀐 후보면 경고 → **이력**(판 생성·손질과 사유, 직전 판 대비 펼쳐 보기, 검토 요청·요청 취소) → 같은 법령 변경·조문의 다른 후보 링크.
- **조별 시행일 표기(T-144)**: 머리말 아래에 같은 호박색 안내 상자(`EffectiveNotesLine`) — 후보를 만들 때의 스냅샷이다. 예정 사내 시행일은 표기와 무관하게 판 시행일 기준 그대로.
- **근거 문구의 출처**(T-177): 변경 근거의 연결 줄(근거 문구) 아래 `출처 vN · 시행 날짜` — 후보를 만들 때의 스냅샷이다. 본문에서 찾은 근거 문구가 기준 본문에 없으면 `기준 본문(vN)에 없는 문구`. T-177 전에 만든 후보에는 표시하지 않는다
- **승인·반려**(T-108, 관리자·검토 중일 때만 — 편집자에게는 보이지 않는다): `승인 · 반려 (판 N)` 카드 — 사내 규정 시행일(달력, 오늘 이전 선택 불가, 기본값 없음, "참고: 법령 시행일 …"), 개정 사유(필수, `사유 초안 넣기`로 "법령명 조항 개정 반영" 채움), 법령 시행일보다 이르면 "이르게 시행하는 이유"(필수) 칸이 나타난다. 날짜를 고르면 "새 버전이 발행되고 그날부터 시행 — 그날 전까지 시점 조회는 지금 본문" 요약. `승인 — 후속 버전 발행`. 막히면(409) 빨간 안내에 원인과 날짜·버전이 나오고, 기준이 어긋난 경우 `그 날짜 기준으로 다시 만들기`(새 후보로 이동), 시행일 미기록이면 규정 화면 링크, 그 시행일에 조문이 폐지돼 있으면 안내만(반려로 닫는다, T-126). 아래 반려 사유(필수) + `반려 — 발행하지 않음`. 승인 뒤: 초록 배너 "승인됨 — vN · 사내 시행일 날짜(시행 예정) · 발행 날짜 시각(한국 시각 — 곧 승인 시각) · 법령 시행일 날짜(+ `법령보다 조기 시행`) · 승인 승인자 · 개정 사유(조기 시행 이유 포함) · 규정에서 보기"(날짜 3종, T-111), 승인·손질 카드는 사라진다. 반려 뒤: 장미색 배너 "반려됨 — 판 · 반려자 · 시각 · 반려 사유 · 고치면 작성으로", 손질은 남는다. 이력에 "승인 — 후속 버전 발행"·"반려"·"반려 뒤 손질 — 작성으로".
- **변수 값**(T-109 ②): 머리말에 `예정 사내 시행일`. 바뀐 곳을 누르면 변수 근거 카드(보라 — 법령 근거와 따로: 변수·`{{키}}`·"이전" → "값"·예정 사내 시행일에 맞는 값·값의 유효기간·범위 "이 회사"). 아무것도 고르지 않으면 개요에 변수 값 목록(→ "값" 넣음 / 이미 그 날 값 / 넣지 않은 까닭). 후보를 만든 뒤 값이 바뀌면 "예정 사내 시행일(날짜)의 변수 값이 바뀌었습니다" 안내와 다시 만들기. 승인 카드에 "이 후보의 변수 값은 예정 사내 시행일 기준 — 다른 날로 승인하면 그 날 값과 다를 때 다시 만들어야", 409 `variable_changed` 면 원인(변수 "이전" → "그 날 값")과 `그 날짜 기준으로 다시 만들기`. 다른 후보로 옮기면 고른 변경을 푼다. 목록 배지 `변수 값 바뀜`·`조문 폐지됨`
