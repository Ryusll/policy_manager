# v1 - Company Template Platform Rollout

작성일: 2026-04-17

## 목적
- 회사(tenant)별 규정 템플릿을 생성/관리/적용할 수 있는 기반 도입
- 규정 상세/전체화면/인쇄 출력을 템플릿 렌더링으로 통합
- 플랜(Starter/Pro/Enterprise)별 기능 접근 제어 반영

## 백엔드 변경

### 1) 데이터 모델
- `PolicyTemplate` 신규 모델 도입
  - `tenantId`, `name`, `description`, `isDefault`, `isActive`, `layoutJson`, `cssText`
- `Policy`에 `templateId`(nullable FK) 추가
- 마이그레이션 파일
  - `apps/api/prisma/migrations/20260417093000_policy_templates/migration.sql`
- 스키마 변경 파일
  - `apps/api/prisma/schema.prisma`

### 2) 템플릿 API
- 신규 모듈
  - `apps/api/src/templates/templates.module.ts`
  - `apps/api/src/templates/templates.controller.ts`
  - `apps/api/src/templates/templates.service.ts`
  - `apps/api/src/templates/templates.dto.ts`
- 제공 API
  - `GET /templates`
  - `GET /templates/:id`
  - `POST /templates`
  - `PUT /templates/:id`
  - `DELETE /templates/:id`
  - `POST /templates/:id/clone`
  - `POST /templates/:id/set-default`
- `AppModule`에 `TemplatesModule` 등록

### 3) 정책(Policy) 연결
- `CreatePolicyDto`/`UpdatePolicyDto`에 `templateId` 추가
- 정책 생성/수정 시 tenant 스코프 템플릿 검증
- 정책 조회 응답에 템플릿 정보 포함
- 변경 파일
  - `apps/api/src/policies/policies.dto.ts`
  - `apps/api/src/policies/policies.service.ts`

### 4) 플랜/권한 제약
- 템플릿 API 전체에 `@MinPlan('pro')` 적용
- Starter 플랜은 정책 템플릿 연결 불가
- Enterprise만 HTML/CSS 자유편집 허용

## 프론트엔드 변경

### 1) 템플릿 API 클라이언트
- `apps/web/src/api/templates.ts` 신규

### 2) 설정 화면(양식 관리 탭)
- 템플릿 목록/선택/생성/저장/복제/삭제/기본 지정
- Starter는 잠금 안내 + 플랜 비교 모달 연결
- Pro는 기본 빌더 기반 템플릿 사용 가능
- Enterprise는 HTML/CSS 자유 편집 가능
- 주요 변경 파일
  - `apps/web/src/pages/SettingsPage.tsx`
  - `apps/web/src/components/PlanModal.tsx`
  - `apps/web/src/lib/planFeatures.ts`
  - `apps/web/src/i18n/messages.ts`

### 3) 렌더링 통합
- 공통 렌더러 도입
  - `apps/web/src/components/policy-template/TemplateRenderer.tsx`
  - `apps/web/src/components/policy-template/templateUtils.ts`
- 규정 상세/전체화면/인쇄 모두 템플릿 렌더 사용
  - `apps/web/src/pages/PolicyDetailPage.tsx`

### 4) Pro 기본 템플릿 빌더 옵션
- 상단 제목/메타/기준일/조문 제목/푸터
- 로고 표시/로고 높이
- 결재 라인/라벨
- A4 인쇄 규칙/장 단위 페이지브레이크/페이지 번호

## 운영 체크
- 템플릿 생성/수정/복제/기본지정/삭제에 감사로그 기록
- 정책 템플릿 연결 변경은 `policy.update` 감사로그로 추적
- 수동 QA 체크리스트
  - `docs/template-feature-test-checklist.md`

## 알려진 한계 (v1 시점)
- HTML/CSS sanitize는 경량 규칙 기반(정규식)으로 시작
- 복원/이력 확인 UX는 기본 제공 수준
