# 요구 변경 반영

무엇을 만드는가의 원본은 SRS(`docs/Deliverables/03_SRS_요구사항명세/SRS_요구사항명세.md`, 법령 개정 연계는 `18_법령개정연계_설계`)이고, 할 일과 결정의 원본은 작업관리대장이다. 문서를 먼저 고치고 작업으로 내린다. 변경 계획을 보여 주고 승인을 받기 전에는 아무것도 바꾸지 않는다.

변경 요청: $ARGUMENTS

## 1. 현재 상태 확인

- SRS에서 영향받는 요구 ID(AUTH-n, LAW-n 등)와 절을 찾는다.
- 대장에서 관련 T 행(상태 포함)과 D 행을 찾는다. ADR(`10_ADR_의사결정기록/ADR.md`)에 같은 주제의 결정이 있는지 본다.

## 2. 변경 계획

| 변경 유형 | SRS | 작업관리대장 | ADR |
|---|---|---|---|
| 추가 | 해당 절에 새 ID(마지막 번호 다음, 재사용 금지) | 새 T 행(출처에 SRS ID) | 설계 선택이 있으면 새 ADR |
| 수정 | 해당 행 수정, 날짜·T-ID를 함께 적는다 | 영향 T 행의 완료 정의 수정 | 뒤집는 결정이면 새 ADR이 옛 ADR을 대체 |
| 철회 | 취소선 + "삭제(날짜, T-ID)" — 지우지 않는다 | 진행 전 T는 취소, 이미 만든 기능은 걷어낼 T 신설 | 필요 시 |
| 결정(D-xx) | 결정 내용 반영 | D 행에 결정일·결정자·내용, 실제 작업은 T 행으로 내린다 | 필요 시 |

- 완료된 작업의 정의가 바뀌면 완료 기록은 고치지 않고 재작업 T를 새로 만든다.
- 진행 중인 작업이 바뀌면 그 작업을 맡은 세션·사용자에게 알리고 계속할지 묻는다.

"요구 ID / 변경 유형 / SRS 변경 / 대장 변경 / ADR / 영향 작업(상태)" 표를 보여 주고 승인을 받는다.

## 3. 적용

1. SRS·대장·ADR을 고친다. 큰 개정이면 문서 폴더 규칙대로 과거본을 `구버전/`에 남긴다.
2. 결정이 운영 방침이면(예: 임시 운영 방침) 대장 칸반 줄에도 적는다.
3. /shared-commit 으로 문서만 커밋한다(`docs: …`).

## 4. 보고

- 바뀐 문서와 위치, 새로 생긴 T·D, 남은 결정 대기.
- 프로젝트 개요·범위·명령이 바뀌었으면 /claude-md 로 CLAUDE.md를 맞추라고 안내한다.
