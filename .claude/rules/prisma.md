# Prisma 스키마·마이그레이션

- 모델 필드는 camelCase, DB 컬럼은 `@map("snake_case")`, 테이블은 `@@map("snake_case_복수형")`이다(개발컨벤션 2절).
- 스키마를 바꾸면 마이그레이션 파일을 만들어 함께 커밋한다. `db push`에 기대지 않는다.
- 마이그레이션 이름은 최근 것보다 뒤 시각으로 짓고, 다른 세션이 막 만든 것과 겹치지 않는지 커밋 직전에 다시 본다.
- 이미 커밋·배포된 마이그레이션은 고치지 않는다. 바로잡을 것은 새 마이그레이션으로 한다.
- 기존 행이 있는 테이블에 NOT NULL·유일 제약을 더할 때는 기존 데이터를 먼저 채우거나 정리하는 단계를 같은 마이그레이션에 넣는다.
- `prisma format`은 스키마 전체를 다시 쓴다 — 다른 세션의 미커밋 변경이 섞이므로, 내 모델만 손으로 맞추거나 내 hunk만 커밋한다.
