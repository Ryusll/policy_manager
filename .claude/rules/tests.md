# 테스트

- 작업의 완료 정의 항목마다 테스트를 쓰고, 이름이나 describe에 작업 ID를 넣는다(예: `(T-137)`). 입력을 받는 기능은 거부 케이스도 시험한다.
- 테스트가 변경을 실제로 잡는지 확인한다: 변경을 되돌리면 실패해야 한다(revert-to-verify).
- 실패하는 테스트를 지우거나 skip·only로 끄거나 기대값을 구현에 맞춰 고치지 않는다. 테스트가 틀렸다고 보이면 이유를 보고하고 묻는다.
- 통합 테스트(`tests/integration`)는 떠 있는 API를 `helpers.ts`의 `api()`로 부른다. 동시성은 `race.ts`의 도구로 겹치게 만든다(개발컨벤션 7절).
- 공개 회원가입이 닫혀 있어 조직을 만드는 시험은 API에 `ALLOW_PUBLIC_SIGNUP=true`가 필요하다(docker-compose 기본값).
- 법령을 심는 시험은 `afterAll`에서 지운다. 남은 법령이 다른 시험(법령 동기화)의 순서를 바꾼다.
- 가끔 실패하는 통합 시험은 그 파일만 다시 돌려 본 뒤에 코드를 의심한다(부하 때 잠금 타이밍).
