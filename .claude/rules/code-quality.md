# 코드 품질

- 파일 하나는 300줄 이하로 둔다. 240줄을 넘은 파일에 기능을 더할 때는 먼저 나눌 곳을 정한다. 이미 300줄을 넘은 파일에는 새 기능을 새 파일(컴포넌트·서비스)로 빼고 불러 쓰기만 한다 — size-guard hook이 HEAD보다 150줄 넘게 늘리는 수정을 막는다.
- 같은 규칙은 함수 하나에 두고 모든 경로(생성·수정·복원·가져오기·일괄)가 그것을 부른다. 반복된 사고 유형이다(코드리뷰체크리스트).
- 오류를 삼키지 않는다. 빈 catch, 실패를 성공처럼 보이게 하는 기본값을 두지 않는다.
- 새 외부 패키지는 설치하기 전에 사용자에게 묻는다.
- lint는 오류 0을 지키고 `any` 경고를 늘리지 않는다. `eslint-disable`에는 같은 줄이나 바로 위에 이유를 적는다(개발컨벤션 4절).
- 플랜별 제한값은 `apps/api/src/common/plan-limits.ts`의 함수로만 읽는다(개발컨벤션 2절).
